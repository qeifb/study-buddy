# 版本补丁机制

小改动发**补丁包**（几十 KB）就够了，不用让用户重下 238 MB 完整包或 1.6 GB 离线包。

---

## 一、补丁能改什么

补丁只搬「代码文件」，就是解压后清单里的那 **62 个文件**：

| 能改 | 不能改（补丁不覆盖） |
|---|---|
| `app/*.js`、`app/renderer/*`、`app/extension/*`、`app/core/*` | `app/node_modules/**`（含 `electron.exe`） |
| `app/package.json` | `tools/pyenv/**`（python.exe、所有 dll/pyd） |
| `tools/*.py`、`*.ps1`、`*.mjs`、`*.json`、`*.txt` | `tools/models/**`（语音模型） |
| 根目录的 `启动学习通学伴.cmd`、`create-shortcut.ps1`、`README.md` | 单文件超过 8 MB 的 |

判定规则写在 `E:\StudyBuddy\tools\patch-lib.mjs` 里（`DENY_SEG` / `ALLOW_EXT` / `MAX_FILE`）。
如果某一版动了 electron 或 pyenv，生成补丁时脚本会打 ⚠️ 提醒「这一版请发完整包」。

---

## 二、我最常用的两条命令

```bash
cd E:\StudyBuddy

# ① 改动做完后：先把 app/package.json 的 version 改大（例如 0.6.0 → 0.6.1）
node tools\pack-full.mjs
#    ↑ 打完包会自动留档 manifest-0.6.1.json（已存在则不覆盖，保护旧基线）

# ② 生成补丁：拿上一版留档的清单 + 这次的新包
node tools\make-patch.mjs diff ^
  --old-manifest E:\StudyBuddy-Release\manifest-0.6.0.json ^
  --new-zip      E:\StudyBuddy-Release\study-buddy.zip
#    ↑ 产物：E:\StudyBuddy-Release\patch-0.6.0-to-0.6.1.zip
```

**不需要留着上一版的完整包**——清单里已经有每份文件的 sha256，比对足够了。
也可以用 `--old-zip 上一版的包.zip` 代替 `--old-manifest`，两种都行。

加 `-v` 会列出具体改了哪几个文件。

## 三、用户怎么装

1. 把 `patch-0.6.0-to-0.6.1.zip` 解压到**应用根目录**（和 `启动学习通学伴.cmd` 同一层）
2. 双击里面的 `应用补丁.cmd`
3. 看到「补丁应用完成」就好了，双击桌面快捷方式正常用

解压位置放错了不用慌：`apply-patch.ps1` 会自己报

```
[失败] 找不到 app/package.json。
       就把 patch-0.6.0-to-0.6.1\ 整个文件夹挪到
       启动学习通学伴.cmd 所在的那一层再双击。
```

## 四、脚本自己会把关的地方

| 关卡 | 行为 |
|---|---|
| 版本号 | 装过 0.6.1 再装 0.6.0→0.6.1 会提示「补丁的起点和你当前版本对不上」，`y` 才继续 |
| 文件被改过 | 目标文件 sha256 和你本地不一致 → 提示「可能是你自己改过」，`y` 才继续 |
| 占用 | `electron.exe` 还开着 → 检测到被占用就让你先退出，不会强行覆盖（不用重启电脑） |
| 完整性 | 每个文件先校验 sha256 再写，对不上直接退出，什么都不改 |
| 备份 | 覆盖前把原文件复制到 `backup-日期时间/`，装完会告诉你文件夹名 |
| 失败回滚 | 写到一半出错（磁盘满、权限不足）→ 自动把原文件放回去，恢复到应用前状态 |

## 五、两个必须记住的坑

1. **`.ps1` 文件必须带 BOM，`.cmd` 必须 GBK + CRLF。**
   记事本或某些编辑器保存会吃掉 BOM，Windows PowerShell 5.1 就会把中文读成乱码，
   提示全变问号。改完一定要跑一遍编码规整（本目录 `应用补丁.cmd` 是 GBK，别用 UTF-8 存）。

2. **补丁只搬「解压后清单里有的文件」。**
   如果你在工作区加了一个从没进过包的新文件，它不会自动进补丁——
   它会先被 `pack-full.mjs` 的目录白名单（`topDirs` + `rootFiles`）筛一遍，
   只有进了新包的 62 个文件才可能出现在补丁里。
   换句话说：**新文件先在 pack-full 里出现，才可能在补丁里出现。**

## 六、文件清单

| 文件 | 作用 |
|---|---|
| `tools/patch-lib.mjs` | 共享库：判定哪些文件可补丁、算清单、写补丁包、读补丁包 |
| `tools/make-patch.mjs` | 生成侧：`manifest` 出清单、`diff` 出补丁 |
| `tools/apply-patch.ps1` | 用户侧：校验、备份、写入、回滚 |
| `tools/应用补丁.cmd` | 用户侧的双击入口 |
| `E:\StudyBuddy-Release\manifest-<版本>.json` | 每版留档，下次生成补丁要用 |
